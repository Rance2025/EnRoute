# 地图可见视口聚焦设计

## 背景

位置页面的 Mapbox 画布铺满整个窗口，左侧时间/数据面板和右侧上下文面板以悬浮层覆盖在地图上。当前“聚焦当前足迹”和行政区域选择分别直接调用 `map.fitBounds`，只提供统一的四边数值 padding。Mapbox 因而按照完整画布计算相机，没有把左右遮挡区排除，目标边界可能落到面板下方。

这不是足迹或行政区域数据错误，而是地图缺少统一的“用户实际可见视口”相机语义。

## 目标

- 地图继续铺满整个页面，不改变左右面板的悬浮结构。
- 足迹范围、行政区域和单点定位等聚焦行为，都以左右面板之间的实际可见区域为相机视口。
- 目标内容与可见区域四边统一保留 64px 呼吸边距。
- 面板宽度、页面 inset、桌面分辨率或未来左右布局变化时，无需同步修改相机常量。
- 提供可复用的通用聚焦入口，后续地点、轨迹等范围或单点数据不再直接拼装相机 padding。

## 非目标

- 不缩小地图 DOM，也不改变地图在面板后方继续渲染的视觉结构。
- 不调整左右面板的位置、尺寸、间距或共享左栏规则。
- 不重构“显示世界地图”的投影、缩放和地球旋转逻辑。
- 不修改足迹、行政区 MVT、SQLite 或任何数据写入路径。
- 不处理移动端布局；面板隐藏时仅保证通用计算安全退回普通 64px padding。

## 方案选择

采用运行时测量真实遮挡区的方案。每次聚焦发生时读取地图画布、左侧 `.time-context-panel` 和右侧 `.right-context-panel` 的 `getBoundingClientRect()`，据此计算 Mapbox 的四边 padding。

未采用由 `App` 传递面板宽度的方案，因为它需要在 TypeScript 中重复 CSS 的 inset、gutter 和响应式规则。未采用缩小地图画布的方案，因为它会破坏现有全屏地图视觉和悬浮面板结构。

## 结构设计

新增 `apps/web/src/config/mapFocusViewport.ts`，只负责矩形几何计算和 DOM 测量，不依赖 React 或 Mapbox 实例。模块公开两层能力：

1. 纯函数接收地图矩形、可选左右面板矩形和安全边距，返回 `{ top, right, bottom, left }`。
2. DOM 入口从地图节点所属 `.app-shell` 查询左右面板，读取矩形后调用纯函数。

`MapboxCanvas` 新增共享的可见视口相机入口：

- 范围聚焦接收 bounds 与 duration，在调用 `map.fitBounds` 前实时获取 padding。
- 单点聚焦接收 center、zoom 与 duration，在调用 `map.flyTo` 时使用同一 padding，并设置 `retainPadding: false`，避免一次聚焦改变后续用户相机操作的全局 padding 状态。

行政区域选择和“聚焦当前足迹”统一改走范围聚焦入口；“定位当前位置”改走单点聚焦入口。世界地图继续使用现有专用逻辑。

## 几何规则

统一安全边距为 64px。

- `top = 64`
- `bottom = 64`
- `left = 左侧有效遮挡宽度 + 64`
- `right = 右侧有效遮挡宽度 + 64`

左侧有效遮挡宽度是地图左边缘到左面板右边缘的水平距离；右侧有效遮挡宽度是右面板左边缘到地图右边缘的水平距离。计算时把面板矩形裁剪到地图矩形内，并且只接受与地图存在有效二维交叠、宽高和坐标均为有限值的面板。

当面板不存在、隐藏、尺寸为零、位于地图外或测量无效时，对应侧不增加遮挡宽度，退回 64px。结果不得出现负值或非有限值。

## 数据流

1. 用户点击足迹聚焦、选择行政区域或完成浏览器定位。
2. `MapboxCanvas` 在动作发生时读取当前地图节点和所属 shell，而不是缓存窗口初始化时的面板宽度。
3. 通用测量函数得到当前左右遮挡宽度，并加入 64px 安全边距。
4. 范围目标调用 `fitBounds`；单点目标调用 `flyTo`。
5. Mapbox 按不对称 padding 计算相机，使目标完整落在中间可见区域。

实时测量保证窗口尺寸或面板布局变化后，下一次聚焦直接使用最新几何，无需额外维护 ResizeObserver 状态。

## 失败与降级

- 地图节点尚未挂载或地图实例不存在时，保持当前无操作行为。
- 找不到 `.app-shell` 或左右面板时，使用四边 64px。
- 任一面板测量异常时只忽略该面板，不阻断另一侧计算和聚焦动作。
- 地理定位权限拒绝或定位失败继续沿用当前行为，本次不新增提示流程。

## 测试设计

### 纯几何测试

在 `apps/web/src/config/mapFocusViewport.test.ts` 覆盖：

- 对称左右面板：左右 padding 等于各自遮挡宽度加 64px。
- 非对称面板：左右分别按实际遮挡计算，不假定两侧宽度相等。
- 面板带页面 inset：从地图边缘计算到面板远端，确保面板外侧狭窄地图区域不被误算为可见工作区。
- 面板隐藏、零尺寸、越界或无效：对应侧退回 64px。
- 面板部分超出地图：遮挡宽度被裁剪到地图范围内。

### 组件测试

更新 `apps/web/src/components/MapboxCanvas.test.tsx`：

- “聚焦当前足迹”使用动态四边 padding，不再使用数字 `96`。
- 选择行政区域使用同一动态四边 padding，不再使用数字 `72`。
- 定位当前位置通过共享单点聚焦入口传入动态 padding，并且不保留相机 padding。
- 缺少 shell/面板测量时三个入口都安全退回四边 64px。

### 浏览器验收

在桌面视口中分别验证足迹聚焦、行政区域排行选择和当前位置定位：

- 目标点或完整范围没有被左右面板遮挡。
- 目标与中间可见区域四边至少保留约 64px。
- 地图仍铺满整个页面，左右面板布局不变。
- 足迹、行政区边界、地图工具条和控制台没有新增异常。

最后运行 `npm test`、`npm run lint` 和 `npm run build`。改动前已稳定复现的无关基线失败 `AccountingPage.integration.test.tsx` 中“空当前月时请求最近导入月份”用例应单独记录，不在本任务中修改。
