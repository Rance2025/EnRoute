# 区域排行榜比例与选中态优化设计

## 背景

区域页右侧排行榜已经收紧为 `24px` 行高的横向条形图，但当前仍有三项体验问题：排行名称字重偏重；柱体通过 `Math.max(0.08, ...)` 强制保留至少 `8%` 长度，导致榜尾数值失真；柱体使用圆角且 hover/focus 通过整行灰色铺底反馈，视觉上不够像连续的数据图表。

此外，应用已经持有 `selectedAdminRegion` 并用它驱动地图聚焦和行政区填充，但该选中 ID 没有传回右侧排行榜，因此右栏没有真正的持久选中态。

## 目标

- 保持排行榜行高 `24px`、五行最大高度和超过五行滚动不变。
- 行政区名称字重从 `820` 降为 `600`。
- 柱体高度从 `12px` 降为 `8px`。
- 柱体完全直角，不保留任何圆角。
- 默认柱色使用略淡的 `#3d8f7d`；hover 与选中态恢复当前强调色 `#2c8572`。
- 删除 hover/focus 的整行灰色背景。
- 正数比例低于 `2%` 时显示为 `2%`；真实值为 `0` 时保持零长度。
- 点击排行后，右栏持久标识当前地图所选行政区。

## 比例规则

柱长继续以当前完整排行榜第一名的足迹点数量为最大值，计算规则明确为：

```ts
if (maxFootprintCount <= 0 || footprintCount <= 0) return 0
return Math.max(0.02, Math.min(1, footprintCount / maxFootprintCount))
```

因此：

- 榜首显示 `100%`。
- 普通正数显示真实比例。
- 正数但真实比例低于 `2%` 时显示 `2%`，保证仍可辨认。
- `0` 不获得保底长度。

排序、足迹点数量和 API 数据均保持不变。

## 选中与交互状态

`App` 将 `selectedAdminRegion?.regionId` 作为 `selectedRegionId` 传给 `AdminRegionContextPanel`。每个 `RankingRow` 根据 ID 判断是否选中，并在选中按钮上设置 `aria-current="location"` 和 `.is-selected` 类。

状态视觉规则：

- 默认：名称保持深色、字重 `600`；柱体为 `#3d8f7d`。
- hover：名称和柱体变为 `#2c8572`，不增加背景色，不改变布局。
- 选中：名称和柱体持续为 `#2c8572`，即使鼠标移开也保留。
- 排名与右侧数量在默认、hover 和选中态中保持现有颜色，避免整行同时变绿。
- 键盘 `focus-visible` 使用细强调色轮廓，不能通过灰色铺底代替焦点提示。

点击仍调用现有 `onRegionSelect(ranking)`。现有时间范围、行政区层级、导航进入和摘要重试逻辑已经会清空 `selectedAdminRegion`，本次不增加第二套重置状态。

## 组件边界

- `App.tsx`：把当前选中行政区 ID 传给右栏。
- `AdminRegionContextPanel.tsx`：接收 `selectedRegionId`，计算零值/正值比例，并给排行按钮标记选中状态。
- `App.css`：实现 `600` 字重、`8px` 直角柱、默认/hover/选中色和无灰底反馈。
- 既有后端接口、摘要缓存、地图选择填充层和聚焦动画保持不变。

## 测试与验收

- 组件测试验证榜首 `scaleX(1)`、普通真实比例、正数最小 `scaleX(0.02)` 和零值 `scaleX(0)`。
- 组件测试验证 `selectedRegionId` 只给对应排行按钮设置 `aria-current="location"`，点击柱体仍调用现有聚焦回调。
- App 测试验证 `selectedAdminRegion.regionId` 被传入右栏，并继续传给地图。
- CSS 契约测试验证 `24px` 行高、`8px` 柱高、`600` 名称字重、直角柱、默认色、hover/选中色和无灰色行背景。
- 运行排行榜聚焦测试、完整测试、lint 和 build；桌面视口检查滚动、点击聚焦和状态切换。
