# 区域排行榜文字、数字与滚动条细化设计

## 背景

区域页右侧排行榜已经具备单行名称、真实比例柱体、五行最大高度、点击聚焦和持久选中态。当前需要继续收敛三个视觉问题：行政区名称仍然偏重，名称在 hover 和选中时使用绿色会让整行强调过度；数字列缺少千分位并与普通正文共用字体，扫描效率不够；原生滚动条的宽度、箭头和右侧留白还不够精细。

本轮是现有密集产品界面的定向微调。保留当前卡片结构、信息架构、行高、柱体比例和交互语义，不引入新组件库，也不调整手机尺寸。

## 目标

- 行政区名称字重从 `600` 降为 `400`。
- 名称常态使用中灰 `rgba(23, 35, 31, 0.62)`，hover 与选中态使用深灰 `#17231f`。
- 绿色强调只留给柱体：默认 `#3d8f7d`，hover 与选中态使用 `#2c8572`。
- 数字按英文千分位显示，例如 `12,120` 和 `3,013`。
- 数字列复用现有窄体字体栈，并使用等宽数字特性，便于纵向比较。
- 数字列与滚动条之间保留约 `10px` 的稳定间距。
- Chromium 使用 `4px` 常驻细滚动条，隐藏上下箭头，轨道透明，滑块默认低对比度并在列表 hover 时略微加深。
- 保留 Firefox 的细滚动条回退和 `scrollbar-gutter: stable`，避免滚动条出现时横向抖动。

## 方案选择

### 方案 A：CSS 原生滚动条细化

通过标准滚动条属性和 `::-webkit-scrollbar` 系列伪元素处理宽度、箭头、轨道和滑块状态。该方案不增加 JavaScript，不改变滚动行为，成本最低，也与当前列表结构最匹配。

### 方案 B：仅在 hover 时显示滚动条

默认完全隐藏滑块，hover 后再显示。界面会更干净，但可滚动性提示不足，且显示切换容易产生突兀感。

### 方案 C：自定义滚动条组件

使用额外 DOM 与 JavaScript 同步滚动位置。可完全控制视觉，但会引入键盘、滚轮、触控板和可访问性维护成本，不适合本轮轻量调整。

采用方案 A。它能满足用户选择的常驻细滚动条，同时保持原生滚动语义和最小改动范围。

## 组件与格式化

`AdminRegionContextPanel.tsx` 在模块级复用一个 `Intl.NumberFormat('en-US')` 格式化器。排行榜可见数字和按钮的无障碍标签使用同一格式化结果，确保视觉文本与读屏语义一致。

格式化只影响展示，不改变 `footprintCount` 数值、排序、比例计算或 API 数据。现有 `2%` 正数保底和零值零长度规则保持不变。

## 样式规则

`App.css` 保持当前 `24px` 行高、`8px` 柱高、四字符名称列和无轨道柱体。具体调整如下：

- `.admin-region-ranking-card__name` 使用字重 `400` 和中灰常态。
- 名称 hover 与 `.is-selected` 都切换到深灰，不再变绿。
- 柱体默认色、hover 色和选中色保持现有两级绿色。
- `.admin-region-ranking-card__row` 的右侧内边距调整为 `10px`，给数字和滚动条留出稳定空隙。
- 数字列使用 `"Aptos Narrow", "Arial Narrow", "Roboto Condensed", "Helvetica Neue", sans-serif`，字重 `700`、`font-variant-numeric: tabular-nums`、右对齐和零字距。
- WebKit 滚动条宽度为 `4px`；按钮宽高归零并隐藏；轨道透明；滑块使用低对比度深绿灰，列表 hover 时略加深。
- Firefox 继续使用 `scrollbar-width: thin` 和匹配的 `scrollbar-color`。

焦点轮廓、整行点击区域、排名列、名称截断、柱体起点、卡片最大五行高度均保持不变。

## 测试与验收

- 组件测试先写入大数足迹样本，验证可见数字和无障碍标签都输出英文千分位。
- CSS 契约测试验证名称字重与颜色、hover 和选中深灰、数字字体栈与字重、右侧间距以及 WebKit 滚动条规则。
- 先运行新测试并观察预期失败，再写最小实现使其通过。
- 运行相关组件测试和 CSS 契约测试，再运行 `npm test`、`npm run lint`、`npm run build` 与 `git diff --check`。
- 在 `1440 x 900` 桌面视口验证五行滚动、滚动条箭头隐藏、数字右侧间距、千分位、名称常态/hover/选中颜色以及点击聚焦。

完整测试当前存在一个与本任务无关的既有失败：`AccountingPage.integration.test.tsx:100` 预期回调一次但实际为零。本轮不修改记账模块掩盖该失败。

- 不修改地图聚焦、行政区填充和选中状态管理。
