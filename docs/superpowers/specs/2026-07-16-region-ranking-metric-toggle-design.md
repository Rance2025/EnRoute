# 区域排行榜多口径切换设计

## 背景与目标

区域页右侧排行榜目前只按当前时间范围内的足迹点数量排序。用户需要在同一张排行榜中切换三种口径：

- 足迹：按足迹点数量排序。
- 时间：按归属于区域的累计时间排序。
- 距离：按归属于区域的累计移动距离排序。

三种口径继续服从左侧时间范围和“国 / 省 / 市 / 区”层级。切换必须即时完成，不重新请求，不改变地图、缩略图、到访区域计数或排行榜点击聚焦行为。

## 已确认的产品行为

### 排行依据切换

排行榜右上角新增轻量文字切换，固定显示：

```text
足迹 / 时间 / 距离
```

采用视觉讨论中确认的 B 方案：不使用胶囊背景或下拉菜单，选中项通过主题色文字、较高字重和短下划线表达。默认选择“足迹”。切换状态由当前页面会话持有，不写入本地持久偏好。

标题继续按层级显示“国家足迹排行 / 省级足迹排行 / 城市足迹排行 / 区县足迹排行”。标题上方的弱提示固定改为“排行依据”，避免与右上角三个选项重复描述当前口径。

### 排行与地图联动

- 每种口径仅展示当前指标值大于零的区域。
- 按当前指标值降序排列；值相同时按区域名称、区域 ID 稳定排序。
- 排名由前端对当前排序结果重新生成 `1..N`。
- 柱条相对于当前口径第一名计算，继续保留非零值最小可见宽度。
- 切换口径后，如果当前选中区域仍在新榜单中，保留选中和地图聚焦状态；否则清除该选择。
- 列表继续保持五行固定可视高度，更多区域只在列表内部滚动。

## 统计口径

### 足迹

每个足迹点按自身 `timestamp_seconds` 的 Asia/Shanghai 自然日和自身行政区祖先链计数。该规则保持现状不变。

### 时间与距离的区间所有权

按 `timestamp_seconds` 升序排列原始足迹。除第一条记录外，每个当前点承接从上一个点到当前点的完整区间：

```text
previous point ---- interval ----> current point
                                  owns time and distance
```

区间的全部时间和全部移动距离归属于当前点所在区域。在每个行政区层级上，使用当前点 `region_id` 的对应祖先作为归属区域。因此跨区间隔不会因为前后点行政区不同而被丢弃，各区域之和覆盖该层级可解析范围内的全部区间。

本功能不检测定位断档，也不设置最大时间间隔。只要前后时间戳有序，完整间隔都进入统计。第一条足迹没有前驱，不产生时间或距离。

### 距离来源

距离直接使用当前点导入的 `footprints.distance`，其语义是从上一个点到当前点的分段距离，不再对相邻坐标重复计算。

对当前本地数据的只读核验结果为：

- `40,441` 条足迹的 `distance` 均非负。
- 在五分钟内且前后点属于同一区域的区间中，导入距离与坐标 Haversine 距离的比值中位数为 `1.000`。
- 同一批区间的相对绝对误差中位数约为 `0.2%`。

预计算遇到负数、非有限距离或倒序时间戳时失败并保留上一版完整预计算结果，不静默修正事实数据。

### 跨自然日拆分

区间跨越 Asia/Shanghai 自然日时，按午夜边界拆成每日片段：

- 每日时间等于该片段覆盖的秒数。
- 分段距离按每日片段时间占完整区间时间的比例分配。
- 所有拆分片段仍归属于原始当前点的区域祖先链。
- 最后一个片段承接浮点余量，保证各日距离之和严格等于原始分段距离。

这允许任意日、周、月、年和自定义日期范围从每日预计算中直接求和，并保证跨日区间不会全部挤到到达日。

### 可解析范围

国家层级统计全部具有国家祖先的足迹区间；省、市、区层级继续服从当前中国详细行政区数据范围。当前本地 `40,441` 条足迹全部具有 `region_id`。如果后续出现无法解析到某层级的足迹，该区间不进入该层级排行；显式预计算结果需要报告无法解析的行数，不能伪造行政区归属。

## SQLite 预计算

### 表结构

扩展现有 `admin_region_daily_stats`：

```sql
CREATE TABLE admin_region_daily_stats (
  depth INTEGER NOT NULL,
  day INTEGER NOT NULL,
  region_id TEXT NOT NULL,
  footprint_count INTEGER NOT NULL,
  stay_duration_seconds INTEGER NOT NULL,
  travel_distance_meters REAL NOT NULL,
  PRIMARY KEY (depth, day, region_id),
  CHECK (depth BETWEEN 1 AND 4),
  CHECK (footprint_count >= 0),
  CHECK (stay_duration_seconds >= 0),
  CHECK (travel_distance_meters >= 0),
  CHECK (
    footprint_count > 0
    OR stay_duration_seconds > 0
    OR travel_distance_meters > 0
  )
) WITHOUT ROWID;
```

允许 `footprint_count = 0`，因为一个跨日区间可以在某个自然日产生时间和距离，但该日没有原始足迹点。

### 构建与迁移

`npm run prepare:admin-region-summary` 继续作为唯一构建入口。构建器按以下顺序工作：

1. 读取并验证原始足迹、区域元数据和祖先链。
2. 在内存中生成四个层级的每日足迹、时间和距离记录。
3. 在单个事务中创建新结构、写入完整记录并替换旧版摘要表。
4. 更新摘要算法签名和源数据签名。

旧表不具备新增列和放宽后的计数约束，因此迁移使用临时新表后替换 `admin_region_daily_stats`，不能在运行时请求路径执行 `ALTER`、`DROP` 或重建。

写入范围严格限制为现有区域摘要预计算表：

- `admin_region_thumbnail_bases`
- `admin_region_thumbnail_region_paths`
- `admin_region_daily_stats`

不写入或清理以下事实与瓦片数据：

- `footprints`
- `footprint_spatial`
- `visual_tiles`
- `admin_region_tiles`

运行时摘要接口保持独立只读连接。旧 schema、签名缺失或签名过期时返回 `503`，不自动构建、不扫描原始足迹兜底。

## 摘要接口

`GET /api/admin-regions/summary` 的时间和层级参数保持不变。响应继续返回缩略图、到访计数和点位口径的 `visitedRegionIds`，并将单一排序结果改为未排序的区域指标集合：

```json
{
  "depth": 4,
  "visitedRegionIds": ["310112", "310115"],
  "visitedCount": 2,
  "totalCount": 2844,
  "visitedPath": "M...Z",
  "regionMetrics": [
    {
      "regionId": "310117",
      "name": "松江区",
      "footprintCount": 12120,
      "stayDurationSeconds": 3182400,
      "travelDistanceMeters": 428913.42,
      "bounds": {
        "west": 121.0,
        "south": 30.9,
        "east": 121.4,
        "north": 31.3
      }
    }
  ]
}
```

接口按请求日期范围对三个每日字段分别求和。`regionMetrics` 包含任一指标大于零的区域，不携带 `rank`，也不为某个口径重复元数据。前端缓存键仍只包含时间范围和层级，因为同一响应已经包含三种排行所需数据。

`visitedRegionIds`、`visitedCount` 和缩略图继续只表达时间范围内存在原始足迹点的区域，不随排行口径切换。时间或距离因跨日拆分而出现在零足迹日时，可以进入对应榜单，但不会被错误计入“到访区域”计数。

## 前端设计

### 状态与排序

新增排行口径类型：

```ts
type AdminRegionRankingMetric = 'footprint' | 'time' | 'distance'
```

`App` 持有当前口径，初始值为 `footprint`，并传给 `AdminRegionContextPanel`。选择口径时不发请求，只根据当前 `regionMetrics`：

1. 读取对应数值。
2. 过滤零值区域。
3. 按数值、名称、ID 排序。
4. 生成序号、格式化值和相对柱长。

数据源类型校验三个指标均为非负有限数，其中足迹数和时间秒数必须是整数。

### 数值格式

- 足迹：使用本地化整数，不添加单位后缀。
- 时间：小于一小时显示整分钟，小于一天显示一位小数小时，一天及以上显示一位小数天。
- 距离：小于一公里显示整米，一公里及以上显示一位小数公里。
- 数值的 `title` 和行按钮无障碍名称使用未缩写的完整单位表达。

零秒或零米不会出现在对应榜单。格式化只改变显示，不参与排序或柱长计算。

### 控件与无障碍

三个切换按钮置于排行榜标题区右上角，容器使用 `role="group"` 和“排行依据”标签。按钮使用 `aria-pressed` 表达当前状态，并保留键盘焦点样式。行按钮的无障碍名称随口径变化，例如：

```text
第 1 名 松江区，累计时间 36.8 天
第 1 名 松江区，移动距离 428.9 公里
```

加载、错误和重试行为沿用现状。空榜单文案按口径显示“本期暂无足迹 / 时间 / 距离数据”，卡片尺寸不变化。

## 失败处理与一致性

- 显式构建失败时事务回滚，旧摘要继续完整可用。
- 摘要签名过期时运行时返回 `503`，不返回字段不完整的旧协议。
- 时间范围或层级变化继续取消过期请求；口径变化不产生请求，因此不存在口径竞态。
- 地图样式重载、区域边界开关和足迹点可见性不影响排行口径。
- 点击时间或距离榜单仍只使用区域 ID 和 bounds 聚焦，不改变地图数据源。

## 测试与验证

### 后端

- 新表结构、约束、算法签名和旧结构迁移正确。
- 足迹点仍按自身日期和祖先链计数。
- 每个区间完整归属到后一个点的区域，而不是前一个点或二者共同区域。
- 跨区区间在各层级都归入后一个点对应祖先，确保该层级可解析范围内总量不丢失。
- 不设置断档阈值；超长间隔仍完整累计。
- 跨上海午夜的时间和距离按比例拆分，拆分和严格等于原区间。
- 日期范围对三个字段求和正确，包括 `footprint_count = 0` 的指标行。
- 负距离、非有限距离和非法时间顺序使显式构建失败并回滚。
- 运行时接口只读，且不会修改 `visual_tiles`、`admin_region_tiles` 或原始足迹。

### 前端

- 默认显示足迹排行，三个切换按钮及 `aria-pressed` 正确。
- 切换口径不调用摘要接口，排序、序号、柱长和数值同步变化。
- 同值时按名称和 ID 稳定排序。
- 时间与距离格式化覆盖单位边界和完整无障碍文案。
- 切换后保留仍存在的选中区域，清除不在新榜单中的选择。
- 三种空状态、加载、错误和固定五行滚动高度不抖动。

## 非目标

- 不识别停留点、静止状态、交通方式或定位断档。
- 不重建路线，不按道路或铁路补全轨迹。
- 不显示排行百分比或新增区域详情页。
- 不让排行口径改变缩略图、到访区域计数或主地图普通区域过滤。
- 不持久化用户上次选择的排行口径。
- 不修改视觉足迹瓦片、行政区地图瓦片或原始足迹事实层。
