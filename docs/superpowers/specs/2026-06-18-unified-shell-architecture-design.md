# 统一页面壳 A 方案设计

Date: 2026-06-18

## 背景

`在途 EnRoute` 长期会承载位置、时间、金钱三类个人人生数据。当前生产页已经有地图页和记账 MVP，地图页最近形成了“左侧剩余空间 + 右侧单世界地图宽度”的真实布局。用户确认统一页面架构采用 A 方向：顶部居中胶囊导航保持为全局导航，左侧共享时间面板按当前地图页的真实比例动态出现，右侧主工作区沿用单世界地图宽度逻辑。

本设计只记录页面壳方向和交互边界，不开始生产实现。

## 目标

- 为地图、日程、记账等详细分页面建立同构页面壳。
- 保留顶部居中的胶囊导航，作为全局页面切换入口。
- 将左侧区域定义为共享时间/日期/人生阶段面板，而不是某个页面独占的业务侧栏。
- 让右侧主工作区宽度遵循现有单世界地图宽度逻辑，避免回到固定三七分。
- 详细页保持一屏应用感：页面整体不滚动，左侧面板和右侧工作区内部允许局部滚动。

## 非目标

- 不实现生产代码。
- 不做固定 `30/70`、`3/7` 或其他固定比例布局。
- 不改成左侧导航栏。
- 不采用 C 方案，也就是不把胶囊导航只绑定在右侧内容区上方。
- 不做地图、日程、记账的汇总融合页能力。
- 不调整记账数据模型、导入流程、后端存储或地图数据层。

## 生产布局原则

页面壳由三层组成：

1. 全局导航层：顶部居中胶囊，包含品牌和页面入口。
2. 共享时间面板：左侧面板，用于日期、时间范围、人生阶段和时间上下文切换。
3. 主工作区：右侧详细页面内容。地图页是地图，记账页是账目工作台，日程页后续是日程工作台。

布局宽度不由设计稿固定比例决定，而由现有 `src/config/mapPaneLayout.ts` 中的 `calculateSingleWorldMapPaneLayout()` 决定：

```ts
mapPaneWidth = min(viewportWidth, worldWidthPx)
sidePanelWidth = max(viewportWidth - mapPaneWidth, 0)
```

未来实现时，详细页应抽出一个共享的页面壳或布局 hook。地图页继续使用高德地图测得的单世界宽度；非地图详细页需要复用同一套目标宽度，可以先使用当前地图配置下的可计算 fallback，之后再与地图测量结果统一。

窄屏或窗口不足以容纳左侧面板时，`sidePanelWidth` 为 `0`，左侧时间面板收起，主工作区占满视口宽度。

## 胶囊导航

胶囊导航采用 A 方向：相对整个应用视口居中，而不是相对右侧主工作区居中。这样地图、记账、日程和概览之间的切换感保持一致，也保留当前用户喜欢的胶囊视觉。

导航初始入口可以是：

- `概览`
- `地图`
- `日程`
- `记账`

其中 `概览` 可以先是预留入口，是否采用同构页面壳不在本阶段定死。移动端或窄屏下，胶囊需要在安全边距内压缩或允许内部横向滚动，不能遮挡主要内容，也不能导致页面整体横向滚动。

## 共享时间面板

左侧面板的核心职责是控制时间上下文，而不是承载当前页面的主要业务操作。

第一阶段可包含：

- 当前日期或时间范围。
- 小型日历。
- 常用范围：今天、本月、全部、某个旅行或人生阶段。
- 时间线片段或人生阶段列表。
- 当前页面的轻量统计摘要，例如地图点位数、账目笔数、日程数量。

面板内容可以随页面变化展示不同摘要，但骨架和交互位置应保持稳定。面板自身允许纵向滚动，页面整体不滚动。

## 主工作区

主工作区宽度与当前地图单世界宽度一致。详细页不应该在宽屏下无限扩张，也不应该因为记账或日程内容切换而改变整体几何关系。

地图页：

- 继续使用当前右侧地图舞台。
- 后续左侧面板从空白占位演进为时间面板。
- 地图控件、2D 限制、拖拽边界和远山黛视觉规则保持当前地图页约定。

记账页：

- 后续从当前独立页面迁入同构页面壳。
- 左侧时间面板控制右侧账目流水和统计的发生时间范围。
- 右侧保留高密度工作台：账户、流水、编辑、分类树、标签树等内容放在局部滚动区域中。
- 账目记录的创建、管理和统计属于后续实现，不在本设计直接改动。

日程页：

- 后续同样使用左侧时间面板作为日期和范围选择。
- 右侧用于日程、待办和人生事件时间线的详细操作。

概览页：

- 初始可以复用同构页面壳，左侧控制概览范围，右侧做跨位置、时间、金钱的概览。
- 如果后续发现概览页需要更强的汇总表达，可以弱化同构要求，但全局胶囊导航仍保持同一套。

## 视觉方向

整体保持轻、薄、克制的 iOS 感，而不是重型后台仪表盘。

- 色彩继续贴近当前地图页的远山黛、浅海面、低饱和红色强调色。
- 胶囊导航、地图工具条可以使用 pill 形态。
- 工作区内重复卡片和列表项保持克制，边界清晰，避免大面积厚重阴影。
- 不使用重底栏作为主导航。
- 不在应用内写说明性大段文案；页面应直接呈现可操作内容。
- 详细页使用固定视口高度，避免 body 级滚动；溢出内容由左侧面板或右侧局部区域滚动。

## Mock 参考

当前保留的视觉讨论稿是：

`docs/mocks/capsule-single-world-architecture.html`

这个 mock 用 `--map-pane-width: min(100%, 1120px)` 近似展示单世界宽度效果，只是视觉占位。生产实现必须接入现有 `calculateSingleWorldMapPaneLayout()`，不能把 mock 里的固定数值当成真实布局规则。

已否定的方向：

- 左侧导航栏方案。
- 固定 30/70 胶囊方案。
- 胶囊只跟随右侧内容区的 C 方案。

## 实现时的验证要求

进入实现阶段后至少需要验证：

- `calculateSingleWorldMapPaneLayout()` 在宽屏、窄屏和异常宽度下仍返回正确面板宽度。
- 地图页、记账页和后续日程页使用同一套页面壳几何规则。
- 宽屏下左侧面板宽度等于 `viewportWidth - singleWorldMapWidth`。
- 窄屏下左侧面板收起，主工作区不横向溢出。
- 页面整体不产生 body 级滚动；只有指定局部区域可滚动。
- 胶囊导航在地图、记账、日程、概览之间位置稳定且不遮挡关键控件。
- 地图页原有视觉和交互验证继续成立：地图渲染、远山黛样式、隐藏标签、隐藏 POI 点层、2D、无罗盘、拖拽边界、自定义工具条和高德运行时错误检查。
