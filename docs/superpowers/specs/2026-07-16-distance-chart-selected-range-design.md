# 距离图表选中日期范围设计

## 背景

位置页“全部”范围在界面中显示 `2026-01-11` 至今天，但开放式范围会把足迹指标请求转换为 `range=all`。后端随后按数据库实际首末足迹日期生成距离序列。本地数据最后一条足迹是 `2026-06-19`，因此 `2026-07-16` 查看时顶部显示 187 天，图表却只得到 160 个日桶。

## 目标行为

- 所有可编辑时间范围的结束日期不得晚于今天。
- 距离图表始终忠实覆盖选中的开始日期和结束日期，首尾日期均计入。
- 选中范围内没有足迹的日期由后端返回零距离日桶。
- “按日汇总 · N天”中的 N 与图表实际覆盖的选中日期范围一致。
- 日均距离和图表均值仍按截至今天的已过日期计算；由于结束日期不能晚于今天，这与完整选中范围一致。

## 实现边界

地图瓦片和行政区请求继续保留开放式 `range=all` 语义。足迹指标请求不再复用瓦片范围，而是始终使用当前选择的明确 `start`、`end` 参数。后端现有明确日期查询已经逐日生成完整序列，无需新增补零逻辑。

时间选择层负责将结束日期限制在今天。自定义日期输入和日期选择器不能产生未来结束日期；已有范围在规范化时也不得保留未来结束日期。

本次不修改 SQLite 写入代码，不读取或重建 `visual_tiles`，不改变地图瓦片与行政区瓦片的数据路径。

## 测试与验收

- 前端时间范围单元测试覆盖未来结束日期被限制到今天。
- Mapbox 组件测试证明开放式“全部”仍以 `range=all` 请求地图瓦片，但指标接口使用明确的开始、结束日期。
- 组件测试证明图表元数据显示完整选中天数。
- 浏览器在桌面视口验证：`2026-01-11` 至当天显示相同的范围天数与图表天数，最后有足迹日期之后的柱位保持为零。
