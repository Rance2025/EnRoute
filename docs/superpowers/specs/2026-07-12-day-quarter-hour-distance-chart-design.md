# 单日距离图表 15 分钟粒度设计

## 背景

地图页左侧时间面板在“日”模式下把一天距离聚合为 24 个小时桶。24 根柱子只能表达小时级变化，无法看清一天内更短时段的移动节奏。本次把单日距离序列固定改为 15 分钟粒度，一天展示 96 根柱子，并让均值线使用相同的 15 分钟量纲。

周、月、年和自定义范围继续按日聚合。本次不增加粒度设置，也不修改左侧共享面板的尺寸、位置或溢出策略。

## 方案选择

采用后端与前端兼容聚合路径同步生成 96 个真实时间桶的方案。

- 不在前端把每个小时桶平均拆成四份，因为已有小时总量不能还原真实的 15 分钟分布。
- 不增加可配置聚合间隔，因为当前只有单日 15 分钟这一项明确需求。
- 后端指标接口作为地图运行时的主数据源；前端原始点兼容路径保持同一算法，避免两个入口产生不同图表。

## 数据契约

单日 `distanceSeries` 使用以下固定契约：

```json
{
  "granularity": "quarter-hour",
  "unit": "quarter-hour",
  "buckets": [
    {
      "key": "2026-06-19T00:00",
      "label": "00:00",
      "distanceMeters": 100
    }
  ]
}
```

具体规则如下：

1. `buckets` 始终包含 96 项，依次覆盖 `00:00`、`00:15`，直到 `23:45`。
2. `key` 使用 `YYYY-MM-DDTHH:mm`，`label` 使用 `HH:mm`。
3. 第 `n` 个桶覆盖当天起点后的 `[n * 900, (n + 1) * 900)` 秒区间。恰好位于 `HH:15:00` 的足迹进入从 `HH:15` 开始的桶。
4. 每个桶累加其中所有正数 `distance`；零值、负值和非有效距离继续按现有规则忽略。
5. 没有距离的时段补零，不能省略空桶，也不能把相邻空桶合并。
6. 多日序列保持现有 `granularity: "day"`、`unit: "day"` 契约。

后端只对 `footprints` 执行范围 `SELECT` 和分组汇总。本次不写 SQLite，不修改 `visual_tiles`，也不触发任何瓦片构建或清理。

## 前端展示

“日”模式图表使用 96 个等宽列，并复用现有密集图表样式：列之间不留间距，柱子占满各自列宽。图表不增加横向滚动，也不改变左栏高度或宽度。

标题区显示：

```text
按15分钟汇总 · 24小时
```

均值线标签显示真实的每 15 分钟算术均值，例如：

```text
均值 83 m/15分钟
```

柱子悬停或聚焦时继续显示该桶的开始时间和真实距离，例如 `10:15 · 420 m`。现有线性/对数尺度切换只改变柱高和均值线位置，不改变真实标签。现有按横坐标命中列的指针逻辑继续适用于 96 列，键盘焦点仍可落到每个独立时间桶。

## 均值计算

均值与柱子都以单个 15 分钟桶为单位：

- 历史日期：总距离除以 96，范围文案为 `24小时`。
- 当天：总距离除以从当天零点到当前时刻已经过去的 15 分钟等价时长。允许分数，例如 10:20 对应约 41.33 个 15 分钟单位；范围文案仍以小时显示并保留一位小数。
- 未来日期：均值为 0，已过范围为 `0.0小时`。

当天只累加桶起点早于当前时刻的距离，当前正在进行的 15 分钟桶会参与计算。这样当前桶已有的移动距离不会被隐藏，同时分母按真实已过时间连续增长。

平均线位置继续与柱子使用同一线性或对数变换。零距离保持零高度，不为对数计算注入伪造的正数。

## 代码边界

预计改动集中在以下现有边界：

- `apps/api/src/enroute_api/footprints/store.py`：单日 SQL 分桶和固定 96 桶输出。
- `apps/api/tests/test_footprints_api.py`：指标接口与快照兼容接口契约。
- `apps/web/src/layers/footprintTypes.ts`：15 分钟序列类型。
- `apps/web/src/layers/footprintSelectors.ts`：原始点兼容聚合路径。
- `apps/web/src/components/TimeContextPanel.tsx`：聚合文案、单位和当天均值计算。
- 相关前端测试夹具和断言：统一从 24 小时桶迁移为 96 个 15 分钟桶。

现有 CSS 已在超过 90 列时进入密集模式。只有浏览器验证发现 96 列命中或清晰度问题时，才在共享 `.time-context-trend` 样式内做最小调整；不允许在地图页面专属选择器下改变左栏几何尺寸。

## 测试与验证

自动化测试覆盖：

1. 单日指标接口固定返回 96 桶，并正确补齐首尾空桶。
2. `00:14:59` 与 `00:15:00` 分别进入相邻桶，验证 15 分钟边界。
3. 多日指标接口仍返回日桶，不发生契约回归。
4. 前端原始点兼容聚合生成与后端相同的 96 桶、键和值。
5. 单日图表渲染 96 列，并显示“按15分钟汇总 · 24小时”。
6. 历史、当天和未来日期的均值及 `/15分钟` 单位正确。
7. 线性/对数尺度、零值柱、悬停/焦点摘要和横坐标命中在 96 列下保持可用。

实现完成后运行 `npm test`、`npm run lint` 和 `npm run build`。浏览器验证桌面与窄视口下的 96 柱密度、悬停命中、平均线标签、左栏布局和地图渲染，并检查控制台错误。

## 非目标

- 不为周、月、年或自定义范围提供 15 分钟粒度。
- 不增加粒度切换按钮或设置项。
- 不修改足迹距离本身的计算方式。
- 不修改地图瓦片、行政区、轨迹渲染或 SQLite 表结构。
- 不更新 README；仓库启动方式和长期架构事实没有变化。
