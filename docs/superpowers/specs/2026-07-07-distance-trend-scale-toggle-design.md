# 距离图表尺度切换设计

## 背景

左侧时间面板的“当前范围距离”柱状图现在使用线性高度：每个时间桶的距离除以当前范围最大距离。这个模型能表达真实比例，但在长尾数据里可读性差。少数远距离日会把大量普通日压到接近底部，用户难以判断哪些日期有实际活动。

本次只改地图页左侧距离图表的显示尺度，不改距离聚合、均值计算、后端 API、SQLite 或地图瓦片路径。

## 交互

1. 图表默认保持“线性”尺度。
2. 图表标题行增加一个小按钮，点击后在“线性”和“对数”之间轮替。
3. 按钮文案显示当前尺度，例如“线性”或“对数”。点击“线性”进入对数，点击“对数”回到线性。
4. 不做自动切换。即使数据长尾明显，也只由用户手动切换。
5. 当前 hover 或 focus 柱子时，顶部小字继续显示真实距离值，不显示变换后的数值。
6. 均值标签继续显示真实算术均值，例如“均值 54.4 km/日”。尺度只影响均值线在图表里的位置。

## 尺度规则

线性尺度沿用当前规则：

```ts
linear(distanceMeters) = max(distanceMeters, 0)
height = linear(distanceMeters) / linear(maxDistance)
```

对数尺度使用带软拐点的 `log1p`：

```ts
logDistance(distanceMeters) = distanceMeters <= 0
  ? 0
  : Math.log1p(distanceMeters / 1000)
height = logDistance(distanceMeters) / logDistance(maxDistance)
```

选择 1000 米作为软拐点，是因为距离图表的主要阅读单位是“日/小时移动距离”，1 km 以下不应被过度抬高，1 km 以上的长尾才需要逐步压缩。

0 值必须保持 0 高度。不能把 0 替换成 1、0.1 或其他正数再取对数，否则无移动日会被显示成有移动。

均值线使用同一个尺度函数定位：

```ts
averagePosition = scale(realArithmeticAverage) / scale(maxDistance)
```

均值本身仍按现有真实算术均值计算，不改为几何平均或对数平均。

## 组件结构

`TimeContextPanel` 持有本地尺度状态：

```ts
type DistanceTrendScale = 'linear' | 'log'
```

`getDistanceTrendModel` 接收尺度参数，返回：

- 当前尺度。
- 下一个尺度。
- 标题区按钮文案。
- 仍按真实距离格式化的 bucket label 与 average label。
- 按当前尺度计算后的柱高和均值线位置。

样式仍集中在 `App.css` 的 `.time-context-trend` 区域。按钮放在标题行右侧，尺寸要小，不能挤压“按日汇总 · 188天”或 hover 后的日期距离摘要。

## 测试

前端测试覆盖以下行为：

1. 默认使用线性尺度，并保持现有柱高与均值线定位。
2. 点击尺度按钮后切到对数尺度，再次点击回到线性。
3. 对数尺度下 0 距离柱仍是 `0%` 高度。
4. 对数尺度下小距离柱在有极大值时明显高于线性模式。
5. 对数尺度下 hover/focus 文案仍显示真实距离。
6. 对数尺度下均值线按同一尺度定位，但均值标签仍是现有真实算术均值。

视觉验证时检查按钮不破坏标题行布局，密集年视图仍能 hover/focus 到每个桶。

## 非目标

- 不新增自动尺度判断。
- 不新增更多尺度类型。
- 不改距离聚合逻辑。
- 不改会写 SQLite 的代码。
- 不改地图渲染、足迹瓦片或后端接口。
