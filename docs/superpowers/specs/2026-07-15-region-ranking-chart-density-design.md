# 区域排行榜条形图密度设计

## 背景

区域页右侧排行榜已经采用 `排名 | 行政区名称 | 比例柱 | 足迹点数量` 的单行结构，但当前每行最小高度为 `49px`，比例柱只有 `4px` 厚，并带有满宽灰色底轨。这个组合让列表显得松散，也更像五条独立进度条，而不是一张连续的横向条形图。

## 目标

- 保留横向条形排行，不改成由下向上生长的竖向柱状图。
- 保留单行四列结构和四个中文字符宽度的名称列，使所有柱子左端对齐。
- 第一版使用 `24px` 行步进与 `12px` 柱厚，相邻两根柱子之间约留 `12px`，形成接近 `1:1` 的柱厚与垂直空隙比例。
- 删除每根柱子的满宽灰色底轨，只显示实际数据对应的强调色柱体。
- 整个排行行继续作为按钮；点击排名、名称、柱子或数量都快速聚焦对应行政区。
- 保留最多显示五行、超过五行纵向滚动的行为。

## 视觉结构

排行行继续使用四列 CSS Grid：

```text
22px | 4em | minmax(0, 1fr) | auto
排名 | 名称 |      比例柱      | 数量
```

列表不增加行间分割线，也不增加灰色轨道。比例柱的长度仍以当前榜首足迹点数量为 `100%`，其余条目沿用现有比例与最小可见长度计算。柱体使用轻微圆角，但不使用胶囊形满圆角，避免重新产生进度条观感。

行本身保持透明背景；鼠标悬停和键盘聚焦时保留现有轻量背景反馈，提示整行均可操作。名称继续单行截断，并通过 `title` 和按钮 `aria-label` 保留完整行政区名称与足迹点数量。

## 行为与数据

本次只修改前端组件样式和相应布局契约测试。排行数据、排序规则、足迹点计数、行政区层级、摘要接口及地图聚焦回调均保持不变。

点击行继续调用现有 `onRegionSelect(ranking)`，由上层地图逻辑使用该行政区的 `bounds` 完成聚焦，不新增第二套点击处理或地图状态。

## 测试与验收

- 组件测试验证每个排行项仍是完整行按钮，点击名称或比例柱所在行会调用 `onRegionSelect`。
- CSS 布局契约测试验证 `24px` 行高、`12px` 柱厚、无柱体底轨、无行分割线及五行最大高度。
- 运行聚焦测试后执行 `npm test`、`npm run lint` 和 `npm run build`。
- 在桌面视口浏览器实测：五行呈现为紧密连续的横向条形图，柱厚与相邻柱间空隙接近，所有柱子左侧对齐，整行点击可聚焦行政区，超过五行仍可滚动。

## 非目标

- 不修改排行榜数据源、API 或后端预计算。
- 不修改区域缩略图、地图图层或国省市区切换。
- 当前不实现或验收手机尺寸布局。
